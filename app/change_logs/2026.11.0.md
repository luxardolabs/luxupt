## Features

- Read-only accounts: a non-admin keeps browsing, downloads and their own password change, and opens a camera's read-only panel from its card; a test walking every registered route holds new state-changing routes to admin (LUXUPT-145).
- Request ids: `RequestLoggingMiddleware` mints one per request, echoes it as `X-Request-ID`, and the 500 page shows it as the reference. A 422 renders a page or fragment naming the refused fields, never the values (LUXUPT-133).
- The admin user form holds new and renamed logins to the `/setup` login policy (letters, digits, `.`, `_`, `-`) (LUXUPT-107).

## Refactors

- `install_error_handlers(app)` replaces the single Exception handler, installed after the mounts (exception-handler v5).
- `authenticate()` reads the user `with_for_update` + `populate_existing` in the request transaction that issues the session (`fw.single_use_claim_atomic`).
- Typed query inputs: `date` is `IsoDateString`, `interval` is `IntFilter` bounded to SQLite's 8-byte range.
- Post-encode cleanup deletes exactly the frames the worker listed before the encode, chunked at 500 (`app/utils/capture_files.py`).

## Schema / Migrations

- `7c1e4f9a2b3d` (data rewrite): every `users.session_version` becomes a random 62-bit value. All sessions end at upgrade.
- `a4d9e6b01c7f` (data rewrite): strips stream URLs, hosts and aliases from stored capture errors. Not reversible (the redacted text is gone).
- `d2f6a8c41e57` (additive + rewrite): stores every login stripped of surrounding whitespace and adds a unique index on it. **Refuses to run** when two logins collide once stripped, or one is only whitespace (see Release actions).
- Upgrading from 2026.10.1 (where prod is) also runs 2026.10.2's **destructive** `5b8e2d71c4a9` (drops `users.auth_source`).

## Notes

### Deploy runbook (2026.11.0)

Prod runs one site (`PROD_SITE`) on `PROD_NODE`, both set in the gitignored `Makefile.local`, from the gitignored `prod/` directory synced to `PROD_DIR`. It runs 2026.10.1, so this deploy also crosses 2026.10.2's upgrade steps (2, 7). `<host>` below is the site's public hostname.

1. [build host] `make release && make release-public`. Expect: `:2026.11.0` scanned and pushed, then copied by digest to GHCR as `:2026.11.0` and `:latest`, and the GitHub Release `v2026.11.0`. On failure: `make release-public PUBLIC_RESUME=1`; do not deploy until GHCR has the tag.
1. [build host] In `prod/compose.yaml`: set the default tag to `${LUXUPT_TAG:-2026.11.0}`, and set `ALLOWED_HOSTS: <host>` (2026.10.2 refuses `localhost` / `127.0.0.1`; the healthcheck reaches `/health/live` from loopback without them). Verify: `docker compose -f prod/compose.yaml config -q`.
1. [build host] `make prod-backup`. Expect: `<site>_<ts>.db` listed under `PROD_DIR/backups/YYYY/MM/DD/`. On failure: stop; do not deploy without a backup.
1. [prod node] Collision check for `d2f6a8c41e57`: `docker exec luxupt-<site> python -c "import sqlite3;c=sqlite3.connect('/app/luxupt/output/timelapse.db');print(c.execute('select lower(trim(username)),count(*) from users group by 1 having count(*)>1 or trim(username)=\"\"').fetchall())"`. Expect: `[]`. On anything else: rename per Release actions before step 5.
1. [build host] `make prod-sync && make prod-deploy`. Migrations `5b8e2d71c4a9`, `7c1e4f9a2b3d`, `a4d9e6b01c7f`, `d2f6a8c41e57` run on start.
1. [prod node] `docker ps --filter name=luxupt-<site>` until `healthy`, then `curl -sk -o /dev/null -w '%{http_code}\n' --resolve <host>:<port>:127.0.0.1 https://<host>:<port>/health/live`. Expect: `200`. On failure: `make prod-logs`; a stop on an unknown revision or a refused migration names its cause.
1. [prod node] `docker exec luxupt-<site> python -m app.cli reset-password <username>`. Expect: a one-time password; sign in and set a new one at `/account/password`. The env login is retired since 2026.10.2.
1. [browser] Sign in, open Cameras, Images and Timelapses; confirm captures are arriving.

Rollback: stop the stack, restore the step-3 backup over the site's `timelapse.db` under `PROD_DATA_ROOT` (delete its `-wal` / `-shm`), then `make prod-rollback TAG=2026.10.1` with the step-2 changes reverted. A downgrade through the migrations is not the path: `a4d9e6b01c7f` cannot restore redacted text.

### Release actions

- LUXUPT-162: Login migration `d2f6a8c41e57` runs on start and refuses, changing nothing, when two logins match once stripped or a login is only whitespace; rename one with `UPDATE users SET username = ? WHERE id = ?` from a one-off container of the stack's image, then start again (runbook step 4). Rolling back past this release needs `alembic downgrade a4d9e6b01c7f` first, run with the new image. New and renamed logins on the admin user form follow the `/setup` policy. Every response but a 500 carries `X-Request-ID`; request log lines name the route template and no longer the submitted username on a failed sign-in.
