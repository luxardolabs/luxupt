## Schema / Migrations

Nine revisions. Two matter on deploy:

- `a2d380f58938` — **baseline schema (additive, structural).** The chain had six revisions and ZERO `create_table`: `alembic upgrade head` on an empty database died on revision 001. The schema was only ever built by `create_all`, so migrations had never been exercised from empty and no fresh provisioning path worked. Baseline added, chain re-rooted. `alembic heads` still resolves for existing deployments, which are unaffected.
- `9f3d0d41053d` — **data backfill (non-destructive).** Fills `camera_id` on timelapse rows written with `""`, only where the safe name resolves to exactly one camera. Downgrade is a no-op.
- `c4e7b1a90f22` — **timestamp conversion (data, reversible).** Converts the 14 application-written columns from naive-local to UTC. Excludes `created_at`/`updated_at` on the `TimestampMixin` tables — those carry `server_default=func.now()` and SQLite's `CURRENT_TIMESTAMP` is ALREADY UTC, so shifting them would break them. `jobs.created_at` is not one of those and IS shifted. Converted per-row in Python, not as a SQL `'+N hours'`: the offset is not constant. Verified on a copy of a live database (423k rows) — CST `12:00 → 18:00` (+6h), CDT `12:00 → 17:00` (+5h), the ambiguous repeated hour to the first occurrence. A flat `+6` would have been an hour wrong on every summer row.
- `MetaData` now carries the canonical fleet `naming_convention`.

## Infra / Ops

- **ONE `compose.yml`**, and the first compose file this repo has committed. The base file, four per-site-per-env overlays and the separate nginx file collapsed into one: every per-site and per-env difference is a value in a gitignored `.env.<env>`, and nginx is a `profiles:` key. It is committed because it carries no topology — registry, tag, ports, cert root and storage paths are all interpolated. Four env files exist and each was verified with `docker compose --env-file <f> config`.
- **Python 3.13 → 3.14** across pyproject, both Dockerfile stages and `[python].target`; lock regenerated.
- **`make check` is the canonical gate**: `guard-version-check honest lint mypy test db-verify arch audit gitleaks`. The previous gate silently omitted mypy and gitleaks. `guard-version-check` is now FATAL — a stale pin fails instead of printing a warning nobody acts on.
- **`make db-verify`** — fresh empty DB → `alembic upgrade head` → diff vs models, failing on ANY structural diff. This is what caught the missing baseline.
- **Test isolation** — the suite sources a dedicated `TEST_DATABASE_URL` with a dev-DB guard; `make test` creates and wipes the throwaway database.
- **`make lock` was broken** — poetry 2.x removed `--no-update`, so the target failed outright. It now runs poetry in Docker at the Dockerfile's pin.
- **`make docker-setup` refuses a stray buildx builder** (`repo.buildx_strays_refused`). `buildx create` only CREATES, so a repo that migrated to the shared builder leaves its old daemon running forever, uncapped. Proven by creating a real stray and watching it refuse.
- **Guards** luxarch 0.153.0 → **0.194.1**, luxlint 0.45.1 → **0.55.0**, luxaudit 0.4.0 → **0.9.0**. Emitted assets re-emitted rather than hand-edited (hooks, the route-smoke asserter v12, the `guard-upgrade` recipe).
- **Internal topology removed from the committed tree** — the Makefile prod block parameterised, real values in the gitignored `Makefile.local`, a personal name removed from the startup banner. **Repository history scrubbed and republished** (LUXUPT-74): `main`, `dev` and the `v1.1.5` tag all replaced; neither leak commit is reachable from any remote ref.

## Fixes

- **Nine render-time 500s**, every one on a live route, none visible to arch, lint, mypy or audit. Two handlers passed the wrong context keys (`/images/partials/filters`; `/system/about` read one dict under key names only `/system` used). The camera panel read four attributes `Camera` does not have (`type`, `model`, `firmware_version`, `host`) — written against a richer Protect payload than the model stores. The job card read `job.image_count` where the column is `total_frames`. A four-state result partial dereferenced a flag NOTHING sets, breaking every failure path and the detect route's success path. And a scheduler save wrote `None` into NOT-NULL columns whenever the form omitted the encoding fields.
- **The component showcase was validating a shape the model never had** — its pending-job fixture carried the invented `image_count`, so the macro was written against the fixture and the showcase stayed green while the live polling endpoint 500'd.
- **Password hashing was one release from breaking.** passlib's argon2 handler reads an `argon2.__version__` that argon2-cffi is removing — a `DeprecationWarning` in production, a raised exception under `filterwarnings = error`. Argon2 now goes through argon2-cffi directly; the wire format is unchanged so stored hashes still verify (checked against a live hash). No bcrypt fallback: `bcrypt` was never in the lock, so that advertised legacy path could only ever have raised, and neither live database holds one.
- **GET page renders wrote to the database.** The settings CRUDs were lazy get-or-create and the users page synced the env user on every render, so 13 GET routes reached a write — CSRF-reachable under `SameSite=Lax` (`fw.state_changing_get`, now 0).
- **Two camera links returned nothing** — "View Images" and "Timelapses" sent `safe_name` into a `camera_id` (UUID) column. The same mismatch made the "timelapse already exists" check never fire, so finished work could be re-encoded.
- **13 timelapse rows were invisible to the UI** — a retired code path wrote `camera_id=""`. Repaired by migration `9f3d0d41053d`.
- **A timelapse job could vanish mid-flight** — `JobProcessor.start_job` discarded its `asyncio.create_task` result, so the loop held only a weak reference (ruff RUF006).
- **The cameras page issued 32 queries where 3 suffice** — `get_camera_stats` was called once per camera. Measured on a live copy (8 cameras, 248,844 captures): 32 → 3, 143ms → 85ms, identical results.
- **Video exports stalled every other request** — `_stream_to_file` did a blocking `f.write(chunk)` inside `async for resp.aiter_bytes(...)`, on a download that is streamed precisely to avoid that.
- **Five swallowed exceptions** — legitimate best-effort cleanup that DISCARDED the error, making failure indistinguishable from success.
- **The About page rendered blank values**; **a late-evening capture could be labelled "Tomorrow"**; **a duplicate dict key silently dropped a value** (F601).
- **A flaky test was a real test bug.** `test_tampered_token_rejected` rewrote the LAST base64 character of a JWT signature; that character carries 4 significant bits, so for 3 of 64 values the tamper decoded to the same bytes and the token stayed valid (~4.7% of runs).

## Notes

**Pre-deploy.** Nothing. The chain migrates on start.

**Deploy — one thing that cannot be inferred.** Run the upgrade with `TZ` (or `DISPLAY_TIMEZONE`) set to the zone the existing data was written in. `c4e7b1a90f22` converts stored timestamps from naive-local to UTC and **refuses to guess** an unknown zone; it is a no-op if that zone is already UTC.

**Post-deploy.** `DISPLAY_TIMEZONE` defaults to the container `TZ`, which preserves current behaviour. It is the business-day boundary as well as the display zone: the image and video archives are foldered by local date, so it must match the zone the archive was written under.

**Deferred follow-ups.** LUXUPT-81 (activity retention is built but never wired — 174,451 rows in 7 days on one site, growing unbounded), LUXUPT-77 (the camera panel wants Protect device metadata the app never captures), LUXUPT-80 (wire luxaudit's deptry tail), LUXUPT-73 (the remaining TRIAGE sweeps).
