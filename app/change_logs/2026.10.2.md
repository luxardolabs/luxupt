# 2026.10.2 — 2026-10-31

The database-backed admin bootstrap replaces the env login, every settings form is validated by one schema, every link is built from its route name, and no slow call holds the SQLite write lock.

## Notes

**Before restarting on this version:**

- **`ALLOWED_HOSTS` is required.** The app refuses to start when it is unset, empty, `*` or carries a port. List every hostname the site is reached by, without ports, in each `.env.<env>`. `localhost` is no longer accepted; the container healthcheck reaches `/health/live` from loopback without it.
- **The env login is retired.** `WEB_USERNAME` / `WEB_PASSWORD` no longer sign anyone in; the users table is the only credential store.
  - An existing env account keeps its row with a placeholder hash that verifies against nothing.
  - **After the upgrade, run once per site:** `docker exec <stack> python -m app.cli reset-password <username>`. It prints a one-time password, which must be changed at `/account/password` on first sign-in.
  - On an empty users table the app seeds `INITIAL_ADMIN_USERNAME` / `INITIAL_ADMIN_PASSWORD` once, or else opens `/setup` behind a one-time token printed in the log.
- **Destructive migration `5b8e2d71c4a9`:** drops `users.auth_source`, after flagging the former env account (`auth_source = 'env'`) with `must_change_password`. It adds `users.must_change_password` and `users.session_version`. The downgrade restores `auth_source` and re-marks the `ENV_MANAGED` row.
- **Every image is built from a clean clone of HEAD** (`make publish-sha` / `make release`). `package-lock.json` is now committed for the stylesheet stage.

## Features

- Admin bootstrap (luxarch's emitted admin-bootstrap set):
  - first-boot `INITIAL_ADMIN_*` seed, or `/setup` behind a one-time logged token;
  - `python -m app.cli reset-password <username>` for recovery;
  - a forced change at `/account/password` after a seeded, reset or admin-assigned password;
  - `session_version` in every token, so a password change or reset ends earlier sessions.
- Trusted-host enforcement through luxarch's emitted middleware over a required `ALLOWED_HOSTS` setting.
- Settings forms (fetch, camera, scheduler, backup) each validate through one schema in `app/schemas/settings_form_schema.py` that states every bound its inputs show (LUXUPT-104).

## Refactors

- Every app link is resolved from its route name in the view (`url_path_for`): templates, view services, routers, the rate-limit handler, app.js and the nav bar (LUXUPT-97). luxarch's route-links net (`tests/test_route_links.py`) fails on a template link no route serves.
- Core services return DTOs (`CameraRead`, `CaptureRead`, `JobRead`, `TimelapseRead`, `UserRead`, settings and activity reads) to the views instead of ORM rows.
- Request paths that make a slow call (Test Protect connection, camera Detect, the historical panel, the timelapse video/thumbnail and capture file routes) read their inputs through `app/services/core/_protect_calls_durable.py`, a declared transaction owner (LUXUPT-100).
- `TimelapseService._create_timelapse_record` removed (no caller; owner-approved).

## Infra / Ops

- The SQLite engine begins every transaction `BEGIN IMMEDIATE`. `init_db` runs the auto-vacuum setup on an autocommit connection. A failed migration now stops startup instead of booting a half-migrated app.
- Image code and the venv are root-owned with exact modes (`u=rwX,go=rX`); the runtime user owns only `output/` (`repo.runtime_user_cannot_write_code`).
- luxarch image block, check gate and test-db-bound harness adopted. `make dev-deploy SITE=<site>` publishes an immutable `sha-<commit>`; publishing and release scans run per platform by digest.
- nginx on the fleet line, 1.31-alpine.
- Dependencies: Pillow 13.0.0, certifi 2026.10.23 and mako 1.4.3 (30+ advisories). Non-breaking npm audit fixes in the stylesheet build clear 4 HIGH advisories; 2 moderate remain (LUXUPT-113).
- Guards: luxarch 0.335.0, luxlint 0.72.0, luxaudit 0.15.0.

## Fixes

- Users list Edit/Delete and the camera settings Detect button requested URLs with literal `{{ … }}` in them (a URL passed to a macro as a Jinja string literal).
- Cancelling a job is one conditional `UPDATE … RETURNING`, so a cancel holding a stale RUNNING copy can no longer overwrite a job the worker just completed.
- Settings saves:
  - a request timeout of 0, an unchecked High Quality toggle, a NaN or infinite buffer and over-long scheduler presets no longer save or 500;
  - a failed write no longer logs the Protect password (`hide_parameters=True`);
  - saving Protect settings no longer deadlocks against its own session;
  - a backup directory must resolve inside the output dir.
- `/health`, `/health/ready` and `/metrics` close their transactions, and check the cameras and storage before the database ping.
- Startup camera discovery stores each new camera's detected capabilities even when another camera's write fails (one savepoint per camera); the fetch worker likewise.
- Read-then-write requests (6 of 15 logins under background writes) no longer fail with "database is locked".
