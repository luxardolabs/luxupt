# 2026.09.0 — 2026-09-20

Build timelapses from your NVR's own recordings, a genuinely usable Activity Log, and a long list of things that were quietly not working.

## NEW

- **Timelapses from Protect recordings** `Timelapses` — Build a timelapse for a day you never had live capture running, straight from the recordings already on your NVR. Pick a date range and get either one video per day or a single combined video across the whole range.
- **Choose where frames come from** `Scheduler` — The nightly scheduler can use live captures or Protect recordings. An option you have not configured is shown as unavailable, with what is missing, instead of failing later.
- **The Activity Log is a real page** `System` — It used to be a link to a broken route. It now shows what actually happened, grouped by day, with summary cards, paging, a time range (24h / 7d / 30d / all) and a filter by kind. It opens on Problems, because that is what you go there for.
- **Capture statistics over time** `Cameras` — Charts for capture performance, with back/forward navigation through previous periods and a jump back to the current one.

## IMPROVED

- **The cameras page loads noticeably faster** `Cameras` — It was making 32 database queries to draw the card grid; it now makes 3.
- **Settings pages look and behave consistently** `Cameras · Scheduler · System` — Fields, toggles and buttons across the settings panels are the same components, so spacing, focus rings and keyboard behaviour match everywhere. Buttons that act on a row carry proper labels for screen readers.
- **Times are stored properly and still shown in your local time** `Everywhere` — Timestamps no longer depend on the server's timezone, while everything you see stays local exactly as before. Existing history is converted during the upgrade, so nothing shifts on screen.
- **Recording times shown in your timezone** `Timelapses` — The available recording range displays in the timezone of the browser you are viewing from, rather than the server's.
- **Clearer unavailable states** `Scheduler` — A disabled option explains why ("set a camera API key…") rather than just appearing greyed out.
- **Capture errors say what actually went wrong** `Cameras · System` — The real message from the encoder is kept instead of a summary, and long messages are readable and copyable inline rather than hidden behind a hover.

## FIXED

- **Capture silently stopped when you used more than about five intervals** `Cameras` — Adding a sixth interval could push the next capture hours or years into the future, and everything just stopped with nothing in the logs. Intervals are now independent of each other.
- **Several screens could fail to load entirely** `Cameras · Images · Timelapses · System` — The camera panel, the image filter bar, the About page, the job progress panel and every "save failed" message returned an error page instead of rendering. All fixed, and every page is now loaded by an automated check on each build so this cannot come back unnoticed.
- **Saving the scheduler could fail** `Scheduler` — Saving from a form that did not include the encoding options failed outright.
- **"View Images" and "Timelapses" on a camera returned an empty list** `Cameras` — Both links filtered by the wrong camera identifier and always came back with nothing.
- **"All Dates" on Timelapses showed only the newest day** `Timelapses`
- **A timelapse job could silently disappear** `Timelapses` — A queued job could be dropped mid-encode with nothing in the logs. Jobs are now held for their whole run.
- **Timelapses could be re-encoded unnecessarily** `Timelapses` — The "this timelapse already exists" check never matched, so finished work could run again.
- **Some older timelapses were missing from the browser** `Timelapses` — 13 timelapses existed on disk and in the database but could not be reached through any camera filter. They now appear.
- **A capture late in the evening could be labelled "Tomorrow"** `Images · Timelapses` — The Today / Yesterday labels used the wrong day boundary.
- **Video exports made the rest of the app stutter** `Timelapses` — Downloading a recording from the NVR held up other requests for the length of the download.
- **Some failures disappeared without a trace** `System` — Several clean-up steps threw their errors away, so a failure looked identical to success. They now record what went wrong.
- **The About page showed blank values** `System` — Several settings rendered as empty rather than showing their values.
- **Filters could reject an empty selection** `Images · Timelapses` — Choosing the blank "all" option in a filter could return an error instead of clearing the filter.
- **Backup and user forms did not always close after saving** `System`

## Upgrading

Nothing to do first — the database migrates on start.

One thing to get right: start the upgrade with `TZ` (or `DISPLAY_TIMEZONE`) set to the timezone your existing data was recorded in. This release converts stored timestamps, and it will stop rather than guess if that timezone is unknown. If you already run in UTC, there is nothing to change.
