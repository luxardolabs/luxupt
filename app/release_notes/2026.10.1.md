# 2026.10.1 — 2026-10-09

The jobs page works again while a timelapse is being made, the app refuses requests addressed to names it doesn't own, and a misconfigured camera connection now tells you what's wrong.

## FIXED

- **The Jobs page failed while a timelapse was rendering** `Timelapses` — Opening Jobs (or letting it refresh) while a job was running or queued showed an error instead of the job cards with their progress.
- **A wrong camera-system address gave a cryptic error** `System` — If the address points at a console that isn't running Protect, the health check now says exactly that, naming the address, instead of a parsing error.

## IMPROVED

- **Requests for names the site doesn't own are refused** `Everywhere` — The app only answers the hostnames you list, so links and redirects can't be made to point somewhere else.
- **Clearer, more consistent logs** `System` — Every log line is the same structured format, with the details of each event grouped in one place.
- **Reliability** `Everywhere` — Lots of behind-the-scenes checking work: every deploy is now probed end to end before it counts as done.

## Upgrading

Do these before restarting on this version:

- **Rename the logging settings:** `LOGGING_LEVEL` → `LOG_LEVEL`, `LOGGING_FORMAT` → `LOG_FORMAT`, `LOGGING_MODULE_LEVELS` → `LOG_MODULE_LEVELS`.
- **Set `ALLOWED_HOSTS`** to the hostname(s) you use to reach the site, comma-separated. Without it, only `localhost` is answered, every other address gets an error page, and the app logs a warning at startup.
- **The secure ports are now 11000 (first site) and 11001 (second site).** If you run the bundled nginx, update its `listen` lines and your bookmarks.

There are no database changes this release.
